# Mockups

Photos of blank products used to visualize designs. Each is composited
under a design SVG by `scripts/build-mockups.py` to produce:

- `mockups/<slug>/{lang}.{tee}.{side}.svg` — self-contained preview
  SVGs (tee photo base64-embedded, design inlined with all text
  outlined to `<path>`). Committed so reviewers — and GitHub's
  inline preview — see the design correctly without needing Saira
  Condensed installed.
JPEG rasterizations of these live **outside** this folder, in
`renders/<slug>/{lang}.{tee}.{side}.jpg` at the repo root (generated by
`qlmanage` + `sips` in `build-all.sh`; committed so reviewers can see them
on GitHub). JPEG q82 rather than PNG: the tee photo compresses ~12× better
(~135 KB vs ~1.9 MB per render) with no visible loss.

## Adding a new blank

If we adopt a different product (tote, hoodie, sticker), drop the photo
in here and update `scripts/build-mockups.py` (or fork the constants in
that script) to point at the new file and the new print-area
coordinates. We may eventually want a sibling `.json` metadata file per
blank, but the current setup keeps placement constants centralized in
the build script — simpler while we have one product.

## What belongs here

- Photos of plain blanks (t-shirts, totes, etc.) at the top level.
- Per-design composite SVGs under `mockups/<slug>/` (generated by
  `scripts/build-mockups.py`, committed).
- Vendor product photos for blanks we'll actually print on, **or**
  royalty-free / own-photography.

## What doesn't

- Renders — those go in the top-level `renders/` (JPEG).
- Very large source PSDs (prefer JPG/PNG ≤ 2 MB; the JHK renders are
  ~1.5 MB each).
